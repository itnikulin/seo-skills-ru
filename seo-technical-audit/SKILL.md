# Технический аудит

Выбери образцы главной, категории, карточки, пагинации и фильтра по фактической структуре сайта. Для каждого укажи, должен ли он быть в поиске. Сопоставь путь от внутренней ссылки до конечного HTTP-ответа, директив robots, canonical, ссылки в sitemap и статуса индекса в доступной панели поисковика. Для JS-страниц сравни исходный HTML и отрендеренный контент. При обследовании одного URL укажи границы выборки.

Проверь конфликтующие сигналы. Например, запрет обхода мешает прочитать noindex. Для параметров сравни результат с параметром и без него. Предлагай Clean-param для Яндекса только после проверки, что параметр не меняет значимого содержимого. Для разметки сравни значения с видимым содержимым и требованиями нужного поисковика для конкретного представления. Для локализованных версий проверь канонические адреса, язык и обратные ссылки hreflang там, где это применимо.

Отдай список по влиянию и охвату: URL, воспроизводимое наблюдение, затронутый шаблон, изменение, критерий приёмки. Для скорости отделяй лабораторный тест от полевых данных. Если реальный статус индексирования закрыт, ограничь вывод наблюдаемыми признаками доступности.
